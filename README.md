# LangSOP

LangSOP is the working project for compiling stable Subject-Oriented Programming duties into operational layers such as LangGraph nodes, kernel validators, and surface adapters.

The core rule is simple: SOP remains the semantic proof and authority layer; compiled runtime operators handle stable, frequent, mechanically checkable duties; models re-enter SOP when meaning, authority, ambiguity, or repair requires careful reconsideration.

The v2 pass preserves the initial specification as source snapshots, expands it through a seven-fold specification explosion, and leaves the project ready for kernel schema and operator-contract design. Runtime code still requires solution records, fixtures, and proof before it can claim implementation authority.

The working development pattern is "whole-pie first": keep the product overview and portion map current, mint slices from readiness only when support and proof routes are clear, review completed work for support and requirement deltas, then rebake the whole before the next slice when learning changes the shape of the system.

The final slicing surface isolates work into dependency-closed chunks. FSC1 foundation contracts is accepted as a boundary input, FSC2 planning coordination has been minted into final slices, and downstream chunks stay gated until their upstream contract packs are accepted.

FSC1, FSC2, FSC3, FSC4, and FSC5 have been minted, executed, reviewed, and accepted. The current accepted boundary output is `docs/planning/FSC5_Operations_Safety_Pack.v1.sop`. The post-FSC5 implementation readiness surface is accepted, IR1 final slices are minted, `IR1-S01` through `IR1-S05` are accepted, and the current ready slice is `IR1-S06` completion review and scaffold activation pack, which requires deeper reasoning. No operations control or live machine control is authorized.
